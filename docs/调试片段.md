# 调试片段

逆向卡住时用得上的现成代码。**这些不进发布版** —— 要用就临时贴进 `FloatingBall.install()`
（或别处的 `installAll()`）里，定位完删掉。反正构建只要 2 秒。

为什么不做成模块的常驻功能：用得少（一年几次），而发布版里多一段永远不跑的调试代码是负担。

## 1. 视图树探针：这个 View 到底是什么类

**什么时候用**：屏幕上明明看得见一个东西（悬浮球、悬浮窗），但 `uiautomator` dump 只报基类名
`android.widget.RelativeLayout`，翻反编译又不知道从哪找。

**红果的「一键领」球就是这么破的** —— 遍历出来的 `c42.e` 直接指向了控制器 `y32.o`。

```kotlin
private fun probeViewTree() {
    val onResume = resolver.findMethodByArity("android.app.Activity", "onResume", 0) ?: return
    hooks.intercept("probe-viewtree", onResume) { chain ->
        val result = chain.proceed()
        (chain.thisObject as? android.app.Activity)?.let { activity ->
            android.os.Handler(android.os.Looper.getMainLooper()).postDelayed({
                val root = activity.window?.decorView ?: return@postDelayed
                log.info("视图树：\n${regionNodes(root).joinToString("\n")}")
            }, 10_000)
        }
        result
    }
}

/** 只打落在指定屏幕区域的节点 —— 全打出来太多，按位置圈定。 */
private fun regionNodes(root: android.view.View): List<String> {
    val found = mutableListOf<String>()
    val location = IntArray(2)

    fun walk(view: android.view.View, depth: Int) {
        if (depth > 30) return
        view.getLocationOnScreen(location)
        val (x, y) = location[0] to location[1]
        if (x >= 1000 && y in 900..1500) {   // ← 改成你要找的那块区域
            found += "  ".repeat(depth) + "${view.javaClass.name}  @[$x,$y] ${view.width}x${view.height}"
        }
        if (view is android.view.ViewGroup) for (i in 0 until view.childCount) walk(view.getChildAt(i), depth + 1)
    }

    walk(root, 0)
    return found
}
```

**坐标怎么定**：先用 `./scripts/dev.sh ui` 看当前页面的文字坐标（那是 uiautomator 给的），
待定位的东西位置可以从截图或相邻文字推出来。

## 2. 挂构造函数打调用栈：这个东西是谁建的

**什么时候用**：知道类是哪个了，但不知道**谁**或者**什么时候**建的，想顺着调用者找到挂载点。

`HookManager.interceptConstructors(id, 类, body)` 已经封装好了：

```kotlin
private fun probeWhoCreatesIt() {
    val ballClass = resolver.findClass("c42.e") ?: return
    hooks.interceptConstructors("probe-ctor", ballClass) {
        val frames = Throwable().stackTrace
            .drop(1).take(10)
            .joinToString("\n") { "    ${it.className}#${it.methodName}" }
        log.info("被创建：\n$frames")
    }
}
```

**注意**：这个只对「每次都用 `new` 建」的东西有效。如果是复用的单例，构造函数只在第一次触发，
后面再出现就看不到了。

## 3. 拦 `ViewGroup.addView` 找「谁被加进界面」

**什么时候用**：连类是哪个都不知道，但知道它会被加进某个容器。

**坑**：一定要**放宽过滤条件**。我第一次写的是「只记自定义 `RelativeLayout` 子类」，
结果那个球是**原生 `RelativeLayout`**，被自己的过滤器滤掉了，白跑一轮。

```kotlin
private fun probeAddView() {
    val addView = resolver.findMethodByArity("android.view.ViewGroup", "addView", 3) ?: return
    hooks.intercept("probe-addview", addView) { chain ->
        val child = chain.getArg(0)
        if (child is android.view.View) {
            log.info("入树：${child.javaClass.name} ${child.width}x${child.height}")
        }
        chain.proceed()
    }
}
```

`addView` 调用很频繁，日志会很多 —— 定位完立刻删，别留着。

## 常用手法速查

| 想知道 | 用什么 |
|---|---|
| 这个类在不在、方法签名是什么 | `scripts/jadx.sh <dex> <类名>`（秒级） |
| 这个方法**是不是**真的被调用 | `hooks.probe(id, method)`（只记日志） |
| 谁引用了某个方法 | 反编译目录 grep；`jadx-gui` 的 `xrefs` 更准但要在内存里加载 |
| jadx 反编译不出来 | `scripts/smali.sh <dex>`（smali 一定能出，字段名都在里面） |
| 界面现在长什么样 | `scripts/dev.sh ui` / `shot` |
| 界面该有的东西还在不在 | `scripts/dev.sh smoke fq` |
