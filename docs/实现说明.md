# 实现说明

作用域内有两个 app，实测通过的版本：

| app | 包名 | 版本 |
| --- | --- | --- |
| 番茄免费小说 | `com.dragon.read` | 7.3.7.33 (73733) |
| 红果免费短剧 | `com.phoenix.read` | 7.3.7.32 (73732) |

**两个 app 出自同一套代码**：`com.dragon.read.*` 下的类名、方法名、枚举完全一样，所以「怎么拦」的
机制可以共用。但两件事必须按 app 分开：

1. **策略不同** —— 同一个 `BottomTabBarItemType` 在两个 app 里指的不是同一个 tab（番茄的 `BookStore`
   是书城，红果的是剧场）。见下表。
2. **混淆名不同** —— `com.dragon.read.*` 之外那些被混淆的类，两个 app 各叫各的：

   | 用途 | 番茄 | 红果 |
   | --- | --- | --- |
   | 底部 tab 按钮实现 | `ig7.j` | `ve7.j` |
   | 底部 tab 栏的添加方法 | `BottomTabBarLayout#P1` | `#R1` |
   | 底部 tab 按钮接口 | `ig7.g` | `ve7.g` |
   | 挂件挂载方法 | `PendantController#s` | `#t` |

   所以凡是按混淆名找的地方，都用 `findMethodAnyName` 之类的方式把候选名都试一遍。

### 底部 tab 枚举在两个 app 里分别指什么

| `BottomTabBarItemType` | 番茄 | 红果 |
| --- | --- | --- |
| `BookStore` | 书城 | **剧场** |
| `BookShelf` | 书架 | （不显示） |
| `VideoSeriesFeedTab` | 短剧 | **首页** |
| `LuckyBenefit` | 赚钱 | 赚钱 / 福利 |
| `ShopMall` | 商城 | 商城 |
| `MyProfile` | 我的 | 我的 |
| `BookCategory` | 分类（不显示） | （不显示） |

这张表是从日志里的 `底部 tab：<类型> = <文字>` 行读出来的，不是猜的 —— 那个探针就是为了这个留着的。

下面每条规则记的是：拦的是界面上哪个东西、挂在哪个方法上、为什么挂这里。签名对不上时模块只会跳过
该条并打日志，不会整体失效，所以版本升级后按这张表逐条核对即可。

## 怎么选的 hook 点

番茄的界面大多是「页面自己去问一个开关，然后决定要不要把这块搭出来」。这类开关是最好挂的：
关掉它，后面的视图创建、数据请求都不会发生，页面其余部分不受影响。

尽量不去拦 `View` 的创建或 `setVisibility` —— 那类方法调用太频繁，而且拦下来之后页面自己还以
为组件在，容易出别的问题。

## 一、底部主 tab

两个 app 都挂同一个方法，只是白名单不同：

| | 番茄 | 红果 |
| --- | --- | --- |
| 原底栏 | 书城 ｜ 短剧 ｜ 赚钱 ｜ 书架 ｜ 我的 | 首页 ｜ 剧场 ｜ 商城 ｜ 赚钱 ｜ 我的 |
| 保留 | `BookStore` `BookShelf` `MyProfile` | `VideoSeriesFeedTab` `BookStore` `MyProfile` |
| 结果 | 书城 ｜ 书架 ｜ 我的 | 首页 ｜ 剧场 ｜ 我的 |

| | |
| --- | --- |
| 目标 | `com.dragon.read.pages.main.m#c(android.view.ViewGroup, com.dragon.read.rpc.model.BottomTabBarItemType)` |
| 返回 | 类型不在白名单里时返回 `null` |

底栏上每个 tab 都是这个方法建出来的，建不出来就不会出现在底栏。

让它返回 `null` 是它本来就有的契约：商城在插件没装时、福利在 Polaris 关掉时，走的都是这条路径
返回 `null`，所以调用方已经能接住。

同组的 `bottom-tab-add` 只记日志、不改行为，挂在 `com.dragon.read.widget.BottomTabBarLayout#P1(ig7.g)`
—— 用来确认上面那条确实拦住了。如果日志里还出现该被屏蔽的类型，说明这个版本换了另一条创建路径。

> 红果只做底部 tab 和悬浮球两组 —— 它没有番茄的书城/书架子 tab 和「我的」页那套卡片
> （`lc4.c`、`IBsMineTabCellService` 那几条规则在红果上取不到目标，会打日志跳过）。
> 红果「我的」页上的金币和提现**没有动**，需求里没要求。

## 二、书城子 tab：屏蔽看剧、视频、商城

> 以下二～四组仅番茄适用。

| | |
| --- | --- |
| 要拦 | 书城顶部横滑条里的「看剧」「视频」「商城」 |
| 目标 | `com.dragon.read.model.BookMallDefaultTabData#a(int, java.util.List)` |
| 做法 | 从列表里摘掉要屏蔽的项，再用修正后的下标继续原方法 |

子 tab 列表来自服务端，解析完统一交给这个方法落到 UI 模型上。服务端下发的 `tabType` 实测
「看剧 = 8」「视频 = 16」「商城 = 15」，但**这里按文案匹配而不是按枚举值**：用户看到的、需求里
写的都是文案，按文案拦语义最直白；服务端换文案时这里也要跟着改。

下标修正必须和被删的项在同一轮里算完 —— 原方法接下来会拿这个下标定位当前页，偏一位就会停在错误
的 tab 上。原方法自己删商城时用的也是这套规则（删到当前项就归零，删在前面的就减一）。

## 三、书架子 tab：屏蔽收藏

| | |
| --- | --- |
| 要拦 | 书架顶部横滑条里的「收藏」 |
| 目标 | `com.dragon.read.component.biz.impl.bookshelf.tab.MultiTabShelfFragment#ch(boolean)` |
| 做法 | 进原方法前，把缓存的 tab 清单里名字叫「收藏」的剪掉 |

清单缓存在 `t76.i` 的静态字段 `d` 上，`ch` 每次重建 tab 都会整份读出来，所以在这里剪是幂等的。

`t76.i` 这个类 jadx 反编译失败过，字段名是从别处的引用推出来的；读不到时模块会打日志并把该类现有
的字段名列出来，照着改常量即可。

## 四、我的页：屏蔽金币/微信提现与推荐流

金币那一条是整个「我的」页里最容易漏的：金币、现金余额、微信提现、福利其实是**同一张 Polaris
卡**里的几行，逐个隐藏入口会剩下空壳，整张去掉才干净。

| 规则 | 目标 | 做法 |
| --- | --- | --- |
| `fanqie-mine-coin-card` | `lc4.c#f(vv3.d)` | 卡片类型是 `POLARIS` 就不建这张卡 |
| `fanqie-mine-coin-entrance` | `IBsMineTabCellService#isCellTypeShowable(int)` | 格子编号在 `{2, 119, 124, 134}` 时返回 `false` |

卡片分发器本来就会跳过建不出来的卡（`f` 里对工厂返回 `null` 的情形判过），所以第一条返回 `null`
等于「这张卡不存在」。

第二条挂在**运行时实现类**上而不是接口上（`IBsMineTabCellService$Companion$IMPL$1`）：字节的
ServiceManager 把实现放在接口的 `IMPL` 静态字段里，挂接口本身是挂不上的，由 `ClassResolver`
的 `findServiceImplementation` 解析。

推荐流：

| | |
| --- | --- |
| 目标 | `com.dragon.read.base.ssconfig.template.d#d()` |
| 返回 | `false` |

「我的」页自己按这个开关决定要不要搭推荐流容器。关掉之后容器不会被创建、请求也不会发出去，而页面
的头部、功能入口、订单那些都在这个开关之外。

> 曾经试过挂 `MineTabStaggeredFeed$a.a()` 和跳过 `oe4.d#l(...)` 的数据注入，都没能把推荐流去掉：
> 前者只是这个开关的几个条件之一，后者被跳过之后服务端照样下发默认推荐。真正管用的是 `d#d()`。

## 五、悬浮球 / 悬浮窗

番茄有好几套互不相干的悬浮球，各自由自己的开关决定要不要出现，所以按功能逐个关。

| 规则 | 目标 | 说明 |
| --- | --- | --- |
| *(不拦)* | `ap3.w1` | 「边听边读」功能球 —— **按需求保留**，见下 |
| `float-kmp-continue-attach` / `-showing` | `FloatViewShowManager#j(Context)` / `#o()` | 「继续看」悬浮球（KMP 版），`j` 是它唯一的挂载入口 |
| `float-main-page-show` | `com.dragon.read.pages.main.z#h(android.app.Activity)` | 主页面「继续看」悬浮窗（旧实现） |
| `float-growth-m` / `-tryShowLowTakeCashFloatingView` | `com.dragon.read.polaris.cold.start.l` | 冷启后的增长类悬浮条 |
| `float-pendant-attach` | `PendantController#t(ViewGroup, int, Context)` | 金币/福利挂件（番茄上叫 `s`） |
| `float-pendant-legacy-attach` | `r32.o#t(ViewGroup, int, Context)` | 老式挂件：红果首页右侧竖排的「一键领」 |
| `float-editor-ball` | `ma5.o#g(boolean)` | 信息流右下角的发帖球（没文字的圆按钮） |

**挂件有两套，是独立实现，别以为挂了一个就完了**：

- KMP 版 `com.bytedance.ug.sdk.kmp.novel.pendant.manager.PendantController` —— 两个 app 都有；
- 老式版 `com.bytedance.ug.sdk.novel.pendant`（控制器是混淆名 `r32.o`）—— **只有红果有**，红果首页
  右侧那个竖排「一键领」就是它。

两套各有各的控制器和挂载方法，方法名还都叫 `t`（参数表也一样 `(ViewGroup, int, Context)`），所以
按参数表找就不会认错，但**必须两条都挂**。

挂件那条是本组里最值钱的：`s` 是它唯一的挂载入口，宿主 ViewGroup 和 Compose 承载视图都在里面
创建，不进去就什么都不会贴到界面上。

### 唯一保留的悬浮球：听书「边听边读」球

`ap3.w1`（日志 tag `GlobalPlayerView`，业务名「功能按钮」）**没有拦**。它和上面几个性质不同：

- 你正在听某本书的音频、且这本书有对应电子书时，它飘在界面上（球面是当前书的封面和播放状态）；
- 点它 = 跳回阅读器并同时起播，进入**边听边读**；
- 它自带 `close` 按钮，本来就是用户可关闭的。

也就是说它是功能入口，不是引流组件。当初拦它挂的是 `ap3.w1#s()`（「这次该不该显示」），后来按需求
去掉了。如果哪天又要拦，记住**只关 `s()`，别关 `t()`**：`s()` 内部已经调了 `t()`，而 `t()` 这个
AB 开关还被别处的可用性判断读着，一起关会牵连到功能球之外的逻辑。

发帖球那条绕了一层。`ma5.o` 是这个球的实现类（`EditorEntranceData` + `CollapsingPublishLayout`，
外面套一层 `RoundedView` 做圆形底，中间一个图标，所以看起来是个没文字的圆球）。它由
`CommunityInfiniteEditorHelper` 建出来，建出来就是 GONE + 全透明，**可见与否全看 `ma5.o#g(boolean)`**
—— 那个方法做 alpha 动画再设可见性。

一开始挂在 `CommunityInfiniteEditorHelper#show()` 上，**但没有生效**：书城上显示这个球的路径不走
`show()`（全工程只有 `BsCommunityTabFragment` 调它）。所以改挂 `g` 这个真正的开关，把入参强制成
`false`。全局只有这一个显隐入口，挂它就不会再漏。

## 已知没做的

- `ColdTopicReplyFloatView`（冷话题回复悬浮窗）没有拦。它把 `setVisibility` 从 `View` 继承下来，
  自己没重写，挂基类等于拦全 app 所有 View 的可见性变化，代价太大；它出现的场景也很窄。
  真碰上了再按「谁把它塞进布局」去找挂点。
- `PolarisColdStartManager` 的 `tryShowComic7DayFloatingView`、`tryShowFestivalComicGuideFloatingView`
  两个方法在这个版本里不存在，模块会打日志跳过。

## 环境提示

- `versionCode` 在部分系统上读不到（隐藏 API 限制），日志会写「未知」。这只是诊断信息，不影响规则。
- 模块只在目标 app **主进程**里装规则；番茄还会起 `:sandboxed_process0` 之类的进程，在那里挂界面
  相关的 hook 没有意义。
